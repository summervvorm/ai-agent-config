# Research（一手来源研究）

把研究任务委托给一个**后台 subagent**，让它去读一手来源，你同时可以继续做别的事情。

## 触发时机

- 用户想研究某个话题，需要从官方文档/源码/规范等一手来源取事实。
- 需要收集某个文档站点、API 的事实信息，而不是二手转述。
- 用户希望"把阅读脚力"委托出去，让你边读边做其他事。
- 需要查证某个论断是否落到一手出处上。

## 工作流

1. **后台启动 subagent**：用 `subagent` 工具（默认后台运行）把研究任务一次性委托出去，prompt 必须自包含（子代理没有本会话的上下文）。
2. 研究期间你继续处理其他工作；subagent 完成后你会收到结果通知。
3. 需要立即拿到结果时，用 `run_in_background: false` 等待其返回。
4. 过程中可先用 `web_search` 快速定位一手来源的入口/URL，再让 subagent 深入读。

## 步骤（给 subagent 的委托说明）

让后台 subagent 执行以下任务：

1. **只对一手来源调查**——官方文档、源码、规范（spec）、第一方 API，而不是它们的二手转述。把每个论断都追回到"拥有它"的来源。
2. **把研究发现写进单个 Markdown 文件**，逐个论断注明其来源（URL 或源码路径等）。
3. **保存位置遵循仓库已有约定**——如果仓库已经有存这类笔记的目录，放进去；没有就放到一个合理的位置，并明确告诉用户放在哪里。

也可结合 `web_search`：先搜官方来源的入口，再读一手页面/文档。

## 检查清单

- [ ] 委托给了后台 subagent（除非需要立即结果）。
- [ ] subagent 的 prompt 自包含：说明要研究的问题、要查的一手来源类型、输出文件路径与格式、每个论断都要附来源。
- [ ] 结论来自一手来源，不含无出处的二手断言。
- [ ] 输出是单个 Markdown 文件，每个论断注明来源。
- [ ] 文件放在仓库已有约定位置（无则自定并说明）。

# 知乎内容多维度分析器

## 概述

本技能对知乎平台上的问题进行系统化的多维度分析，生成一份结构化的分析报告，输出到 Obsidian Vault 的知乎分析专项目录下。

## 触发条件

当用户执行以下操作时触发本技能：
- 提供知乎问题链接（如 `https://www.zhihu.com/question/...`）
- 粘贴知乎问题的标题和内容
- 粘贴知乎回答的文本内容
- 要求"分析知乎"、"知乎分析"、"评价这个知乎问题"
- 讨论某个知乎热点话题并要求深入分析

## ⚠️ 强制工具使用约束

### 信息获取优先级（严格遵守）

**WebSearch 不可用声明：**
`WebSearch` 和 `WebFetch` 工具在此环境中**完全不可用**（被企业安全策略阻止，且 DuckDuckGo 搜索始终返回空结果）。严禁使用这两个工具。

**唯一可用的信息获取方式：**

| 优先级 | 工具 | 说明 |
|--------|------|------|
| 1（首选） | `mcp__search-service__fetch_url` | 通过 DrissionPage Chromium 浏览器模拟获取知乎页面完整内容，支持反爬。**获取知乎内容的唯一方式。** |
| 2（备选） | `mcp__search-service__web_search` | DuckDuckGo 搜索，当前返回空结果的概率较高，仅作为尝试性补充。**不能依赖。** |
| 3（备选） | `mcp__search-service__wikipedia_search` | 获取话题背景知识，当前可能受网络限制（403）。 |
| 4（备选） | `mcp__search-service__github_search` | 仅科技类话题按需使用。 |

**强制规则：**
- **禁止使用 `WebSearch` 工具** — 它在此环境中完全不可用，每次调用都会浪费一次工具调用且返回空结果。
- **禁止使用 `WebFetch` 工具** — 无法绕过知乎的安全策略。
- **知乎页面内容获取必须且只能通过 `mcp__search-service__fetch_url`**。
- 获取知乎内容时，使用 `mode="auto"` 和 `extract_text=true` 参数。
- 如果 `fetch_url` 也失败，在报告中明确标注"无法获取页面内容"，并根据用户已提供的信息进行有限分析。

### MCP fetch_url 调用方式

由于 `mcp__search-service__fetch_url` 作为 MCP 工具的名称带有冒号前缀，在实际调用中可能需要在 Bash 中通过 Python 脚本直接调用。以下为两种可用方式：

**方式一：直接通过 MCP 工具调用（如果环境支持）**
```
mcp__search-service__fetch_url(url="<知乎链接>", mode="auto", extract_text=true)
```

**方式二：通过 Bash 调用 Python 脚本（可靠备选）**
```bash
cd "C:\Users\20301\Documents\trae_projects\python_search_mcp" && python -c "

sys.path.insert(0, '.')
```

## 分析框架

### 第一阶段：信息收集

在开始分析前，需要从用户提供的内容中提取以下信息：

1. **问题元数据**：问题标题、问题描述、提问时间、问题标签/话题
2. **回答数据**：每个回答的答主信息、赞同数、评论数、收藏数、转发数、发布时间
3. **评论数据**：热门评论内容、评论点赞数、评论回复数

如果用户提供了 URL 但未提供完整内容，**必须使用 `mcp__search-service__fetch_url`** 抓取页面内容。

### 第二阶段：多维度分析

按以下维度逐一分析，每个维度需要给出分析依据和结论：

#### 1. 话题分类识别

将问题归入以下一个或多个分类，并标注主分类和次分类：

| 主分类 | 子分类示例 |
|--------|-----------|
| 🚻 男女/性别 | 性别对立、女性权益、男性困境、性别角色 |
| 💑 婚恋/情感 | 恋爱关系、婚姻家庭、相亲交友、分手离婚、彩礼嫁妆 |
| 🏛️ 国家/政治 | 国际关系、政策讨论、制度比较、意识形态 |
| 📰 新闻/时事 | 社会热点、突发事件、公共事件 |
| 💻 科技/互联网 | 技术讨论、互联网公司、AI、程序员 |
| 🎓 教育/学术 | 升学考试、大学评价、学术讨论、留学 |
| 💼 职场/就业 | 求职面试、职场关系、薪资待遇、行业分析 |
| 🏠 社会/民生 | 房价物价、医疗养老、社会现象、城乡差距 |
| 🎭 文化/娱乐 | 影视评价、明星八卦、ACG、文学艺术 |
| 💰 经济/金融 | 投资理财、经济形势、商业分析 |
| 🧠 哲学/思想 | 人生意义、价值观讨论、伦理道德 |
| 🔬 科学/科普 | 自然科学、医学健康、心理学 |
| ⚖️ 法律/权益 | 法律案例、权益保护、维权讨论 |
| 🌍 其他 | 无法归入上述分类的内容 |

**分类原则**：
- 一个话题可以属于多个分类，标注主分类（最核心的）和 1-2 个次分类
- 分类应基于问题内容本身，而非回答的倾向
- 如果问题涉及敏感话题，在报告中备注"该话题可能涉及平台内容审核风险"

#### 2. 问题类型分析

识别问题属于以下哪种类型：

- **如何评价类**（"如何评价XXX"）：最常见类型，通常引发观点交锋
- **是什么/为什么类**（"XXX是什么体验/为什么XXX"）：知识型问题，偏客观回答
- **怎么办类**（"XXX怎么办/如何XXX"）：求助型问题，寻求解决方案
- **对比类**（"A和B哪个更好"）：引发比较和争论
- **分享类**（"XXX是怎样的体验"）：个人经历分享型
- **假设类**（"如果XXX会怎样"）：思辨型问题

同时评估问题质量：
- ⭐⭐⭐ 高质量：问题明确、有讨论空间、能引发深度思考
- ⭐⭐ 中等：问题基本清晰，但可能存在引导性或模糊之处
- ⭐ 低质量：问题模糊、钓鱼/引战、无实质讨论价值

#### 3. 回答多维度分析

对每个高赞回答（默认取前 5-10 个，按赞同数排序）逐一分析：

**答主画像**：
- 答主名称（匿名则标注"匿名用户"）
- 是否为认证用户/机构号
- 从回答内容推断的专业背景或身份特征
- 历史回答风格推断（如能从当前回答中看出）

**数据指标**（如果有）：
- 赞同数及排名
- 评论数（反映争议程度）
- 收藏数（反映实用价值）
- 转发数（反映传播力）
- 计算互动率 = (评论+收藏+转发) / 赞同（粗略估计）

**内容分析**：
- **核心观点**：用 1-2 句话概括该回答的主要立场
- **论证结构**：是逻辑推理、个人经验、数据论证还是情感叙事
- **论证质量评分**（1-5分）：
  - 5分：逻辑严密，论据充分，引用可靠来源
  - 4分：论证较完整，有具体论据支撑
  - 3分：有一定道理但论证不够充分
  - 2分：论证薄弱，主要依靠情绪或立场
  - 1分：无实质论证，纯情绪宣泄或人身攻击
- **情感倾向**：正面/负面/中性/混合
- **立场定位**：在话题光谱中的位置（如保守-激进、支持-反对-中立等）

#### 4. 群体画像分析

综合所有回答，分析：

- **观点分布**：支持/反对/中立的比例（粗略估计）
- **主流观点**：获得最多赞同的观点方向是什么
- **少数派观点**：有什么不同但值得关注的视角
- **答主群体特征**：答主们的共性特征（如年龄段、职业背景推测）
- **舆论风向**：整体舆论倾向于哪一方

#### 5. 评论生态分析

- **评论区整体氛围**：理性讨论/情绪化/一边倒/两极分化
- **热门评论观点**：点赞最高的 3-5 条评论及其倾向
- **争议程度**：评论区的分歧程度（低/中/高）
- **评论与回答的关系**：评论是否补充了新的视角，还是主要在附和/反驳

#### 6. 深层分析

- **话题敏感性评估**：该话题在社会舆论中的敏感程度（低/中/高），并解释原因
- **典型叙事模式识别**：识别回答中是否出现常见的叙事模板（如"我有一个朋友"、"人在美国刚下飞机"、"懂得都懂"等）
- **信息茧房风险**：该问题的回答是否可能存在回声室效应，观点是否高度同质化
- **平台特征**：知乎平台特有的文化和现象在该问题中的体现（如"知乎体"、"先问是不是再问为什么"、"理性客观"的自我标榜等）
- **话题延展**：该问题可以延展出哪些更深层次的社会议题

### 第三阶段：生成报告

将以上分析整合为结构化的 Markdown 报告，保存到 Obsidian Vault 的知乎分析目录。

## MCP 工具集成

本技能**仅**使用 `search-service` MCP 提供的工具。以下工具已确认为可用：

### 可用工具及状态

| 工具名 | 状态 | 用途 |
|--------|------|------|
| `mcp__search-service__fetch_url` | ✅ **可用（核心工具）** | 通过 DrissionPage Chromium 浏览器模拟获取知乎页面完整内容（支持反爬）。**获取知乎内容的唯一可靠方式。** |
| `mcp__search-service__web_search` | ⚠️ 不稳定（常返回空） | DuckDuckGo 搜索，仅供尝试性补充。**不可依赖。** |
| `mcp__search-service__wikipedia_search` | ⚠️ 不可用（403） | 维基百科搜索，当前受网络限制。 |
| `mcp__search-service__github_search` | ⚠️ 按需使用 | GitHub 搜索。 |
| `WebSearch` | ❌ **禁用** | 在此环境中完全不可用，禁止调用。 |
| `WebFetch` | ❌ **禁用** | 无法绕过知乎安全策略，禁止调用。 |

### 工具使用策略

**在信息收集阶段：**
1. **【强制执行】** 使用 `mcp__search-service__fetch_url` 直接抓取知乎页面
   - 知乎页面会自动识别并提取结构化数据（问题标题、描述、话题、高赞回答）
   - 如果环境支持直接调用 MCP 工具，使用 MCP 工具；否则通过 Bash 调用 Python 脚本
   - 如果页面包含 js-initialData，会自动提取为结构化的 Markdown
2. **【可选尝试】** 使用 `mcp__search-service__web_search` 搜索背景信息（做好返回空的心理准备）
3. **【可选尝试】** 使用 `mcp__search-service__wikipedia_search` 获取概念定义（当前可能403）

**在深层分析阶段（可选）：**
- 使用 `mcp__search-service__web_search` 尝试获取外部视角
- 如果返回空，在报告中如实标注"网络搜索无结果"

**重要原则：**
- **永远不要调用 WebSearch 或 WebFetch**
- 如果所有 MCP 工具都失败，在报告中标注数据局限性，基于用户提供的内容做有限分析
- 报告中的 MCP 工具使用记录章节如实记录每次调用的结果

## 使用指南

### 当用户提供知乎链接时

1. **【第一步：创建输出目录】**
   ```bash
   mkdir -p "C:\Users\20301\Documents\Obsidian Vault\知乎分析"
   ```

2. **【第二步：获取内容】使用 `mcp__search-service__fetch_url` 抓取页面内容**：
   - 优先尝试通过 MCP 工具直接调用（如环境支持）
   - 如果 MCP 工具不可直接调用，通过 Bash 执行 Python 脚本：
     ```bash
     cd "C:\Users\20301\Documents\trae_projects\python_search_mcp" && python -c "
     import asyncio, json, sys
     sys.path.insert(0, '.')
     from main import fetch_url
     async def main():
         result = await fetch_url(url='<知乎链接>', mode='auto', extract_text=True)
         with open(r'C:\Users\20301\Downloads\zhihu_fetch_result.json', 'w', encoding='utf-8') as f:
             json.dump(result, f, ensure_ascii=False, indent=2)
         print('Done. Length:', len(result.get('text','')))
     asyncio.run(main())
     "
     ```
   - 读取 `C:\Users\20301\Downloads\zhihu_fetch_result.json` 获取完整内容

3. **提取信息**：从抓取结果中提取问题标题、描述、标签、高赞回答

4. **【可选】搜索背景**：使用 `mcp__search-service__web_search` 和 `mcp__search-service__wikipedia_search` 补充外部视角

5. **分析并生成报告**：按照分析框架完成全部分析

6. **保存报告**：保存到 `C:\Users\20301\Documents\Obsidian Vault\知乎分析\知乎分析-{日期}-{关键词}.md`

7. **告知用户**：明确说明报告已保存到 Obsidian Vault 的知乎分析目录

### 当用户粘贴内容时

1. 确认内容完整性（问题+回答+评论是否都有）
2. 如有缺失维度，在报告中标注"用户未提供该部分数据"
3. 使用 MCP 工具补充背景信息（做好可能失败的心理准备）
4. 按照分析框架完成分析
5. 保存到 Obsidian Vault 知乎分析目录

### 当内容不足时

如果用户提供的信息非常有限（如只有问题标题），则：
- 如果有知乎链接，使用 `fetch_url` 获取完整页面内容
- 使用 `web_search` 和 `wikipedia_search` 尝试获取更多信息
- 仅进行话题分类和问题类型分析
- 在报告中明确标注数据局限性
- 建议用户提供更多内容以获得完整分析

## 注意事项

- **保持客观中立**：分析应基于内容本身，不掺杂分析者的个人立场
- **尊重隐私**：不对答主进行人肉搜索式的深度挖掘，仅基于公开信息推断
- **敏感话题处理**：对于政治敏感话题，分析聚焦于舆论生态和论证质量，不做价值判断
- **承认局限**：当数据不足时，坦诚标注而非强行给出结论
- **使用中文**：所有分析输出使用中文，保持知乎社区的语言风格
- **【强制】禁止使用 WebSearch/WebFetch**：这两个工具在此环境中完全不可用，绝对不要调用
- **【强制】知乎内容获取必须走 MCP fetch_url**：这是唯一能绕过知乎反爬的方式
- **【强制】报告输出到 Obsidian Vault**：所有报告必须保存到 `C:\Users\20301\Documents\Obsidian Vault\知乎分析\` 目录下

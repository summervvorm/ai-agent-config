# writing-beats（节拍写作）

把用户的原始素材（raw material）组装成一段"节拍"（beat）旅程。这是一个 **exploit** 性质的任务：探索已经完成、素材堆是固定的——选定一条贯穿素材的路径，然后从素材堆里取料来填满每一个节拍。不要写一大篇，而是像"选你自己的冒险"一样，一节一节（一个 beat 一个 beat）地推进。

## 触发时机

- 用户提供（或即将提供）一段 markdown 原始素材，并要求据此写成一篇文章。
- 用户要求把零散的材料/笔记/访谈记录组织成有节奏、有推进感的叙述。
- 创作类任务：代写、改写、把素材铺成完整叙事。

## 创作方法论（保留）

### Grounding（概念落锚）

每个 **概念**（concept）在被某个节拍使用之前必须先"落锚"（grounded）：要么读者进场时就已经知道，要么在更早的节拍里见过。一个伸手去抓未落锚概念的节拍会失去读者——这是这段旅程唯一不能犯的错。单位是"概念"本身，而不是它的措辞：即使没有术语，一个节拍也可能用上读者尚未具备的某个想法。当概念有名字——即 **术语**（term）——时，落锚就是把"想法"和"术语"一起落地。

概念通过两种方式落锚：

- **先决条件（Prerequisite）** —— 在第一个节拍之前就落锚，读者自带。开始时就定死。
- **引入（Introduced）** —— 由某个节拍建立，从此对之后所有节拍都是已落锚的。

所以每个节拍做两件事：它 **要求（requires）** 已经落锚的概念，同时 **落锚（grounds）** 新的概念。持续维护一份"已落锚清单"，每落一个节拍就更新它。

这正是构造成 choose-your-own-adventure 的力量所在：一个候选节拍只有当它要求的所有概念都已落锚时才能到达；挑选一个落锚了概念 X 的节拍，就会解锁所有在等 X 的节拍。当提供"下一个节拍"候选时，它们必须都从当前已落锚集合可达——并且说明每个会落锚什么，好让用户看到它打开了哪些路径。

最大的杠杆是：哪些做成"先决条件"，哪些放在文章内部落锚。前期要求太多会劝退不具备这些概念的读者；文章内部落锚太多又会让开头几个节拍淹没在定义里。建立先决条件时要与用户确认这一点；每当一个诱人的节拍卡在"某个概念还没被任何节拍落锚"时，回头处理——要么在它前面补一个落锚节拍，要么把该概念提升为先决条件。

### 什么是节拍（beat）

节拍是旅程中的一次移动。它只做一件事——设一个场景、落一个观点、抛一个问题、插一句旁白、翻转一个角度。然后停下来，把读者留在一个能让下一拍转向的地方。

节拍的大小由它所需决定：

- 单句即可，如果这一个移动就够了（例如："然后整整三周什么都没发生。"）。
- 一小段，如果这个移动需要铺垫。
- 多段，如果这个节拍本身是个自足的片段、论证或例子。

如果一个"节拍"需要五个段落加三个小节标题，那它不是节拍——是两个节拍黏在一起。拆开它。

### 从素材堆取料（pulling from the pile）

从原始素材堆取料来填充每个节拍。你可以改写、拆分、重组、或直接引述。素材堆就是一个采石场。

### 结束旅程（ending the journey）

文章在旅程完整时结束——而不是在素材堆清空时结束。绝大多数素材堆都会剩下没有用上的片段。这没有问题；这正是"素材多于所需"的意义所在。

### 写作节奏（writing rhythm）

- 一次只追加一个节拍。绝不超前写。
- 每次写之前都从磁盘重新读一遍文章文件。绝对保留用户的编辑。
- 如果用户大幅改动之前的节拍，让改变后的内容决定之后的走向。
- 如果用户说"重写那个节拍"或"回去换个第 3 拍试试"，照做——就地编辑，其余保持不动。

## 工作流

1. **确定保存路径。** 如果用户没说文章保存到哪里，用 `ask_user_question` 问一次并记住路径。
2. **先确立先决条件（prerequisites）。** 在任何节拍之前，先与用户确定：读者进场时已知哪些概念。这些就是从一开始就"落锚（grounded）"的概念。除此之外的一切，都必须由某个节拍落锚之后，后续节拍才能使用。参见 [Grounding](#创作方法论保留)。
3. **写 2–3 个候选起始节拍**，从素材堆中取材。每个都是进入文章的不同切入点。每个只能基于已落锚的概念；注明每个各自落锚了哪些新概念。**先把候选节拍展示给用户**，再写入文章文件。用户挑选一个。预演一下这选择会解锁哪些节拍——让用户看到路径前方的一小段。
4. 用户选定起始节拍后，**只把那个节拍**写入文章文件。一个节拍可以是一句话，也可以是好几段——就按它自然的样子来。然后停下。
5. **从磁盘重新读一遍文章文件。** 然后给出 2–3 个候选的**下一个节拍**——从文章当前所立之处，旅程可以转向的不同方向。每个都必须从当前已落锚集合可达；注明每个各自落锚什么。
6. 循环第 4–5 步，直到文章到达自然的结尾。

## 检查清单

- [ ] 已问清/确认文章保存路径。
- [ ] 已与用户敲定先决条件（读者进场已知概念），并维护"已落锚清单"。
- [ ] 每个候选节拍都从当前已落锚集合可达；每个候选都注明了它会落锚什么新概念。
- [ ] 一次只地向文章文件追加一个节拍，不超前写。
- [ ] 每次写入前都重新读磁盘上的文章文件，绝对保留用户编辑。
- [ ] 文章在旅程完整时而非素材堆清空时结束。

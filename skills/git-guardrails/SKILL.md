# Git 安全护栏（行为准则）

DSH 没有 Claude Code 那样的 hooks 拦截机制，因此本技能以**行为准则**的形式落地：在模型将要执行任何破坏性 git 命令之前，必须先征得用户确认；在没有办法确认时**默认拒绝**执行，并给出可操作的安全检查清单。目标是防止 push / reset --hard / clean / branch -D 等误操作造成不可逆的数据丢失。

## 触发时机

在下列任一情况出现时立即触发本技能：

- 模型将要执行（或用户请求执行）以下破坏性 git 命令：
  - `git push`（含所有变体，特别是 `--force`）
  - `git reset --hard`
  - `git clean -f` / `git clean -fd`
  - `git branch -D`
  - `git checkout .` / `git restore .`
- 用户主动要求"防止误 push"、"别让我搞坏仓库"、"危险命令先问我"、"给 git 加护栏"。
- 任何涉及删除提交、丢弃工作区改动、强制推送、批量清理未跟踪文件的请求。

## 核心准则

1. **先确认后执行**：上述危险命令不得在用户没有明确同意时静默执行。
2. **默认拒绝**：若无法与用户交互确认（例如信息不足、上下文不完整），一律不执行，改为说明需要确认的理由。
3. **只在自己该做的范围确认**：确认仅针对模型要发起的操作；用户亲自在终端里执行的命令不属于 DSH 拦截范围，但仍可提醒。

## 工作流

### 1. 识别危险操作

在执行任何 git 写入命令前，先检查它是否命中危险清单。命中即进入 `## 步骤 2`。

### 2. 安全检查清单（执行前逐项核对）

在确认前，对照并口头/自检以下各项：

- [ ] 目标分支正确吗？要 push 的分支名、远端（origin）、当前分支是否是你以为的那个？
- [ ] `reset --hard` 会丢弃工作区与暂存区未提交改动——先确认已提交/已备份要保留的内容。
- [ ] `clean -f/-fd` 会删除未跟踪文件/目录——确认没有草稿、生成物或配置文件会被误删。
- [ ] `branch -D` 是强制删除未合并分支——确认该分支上的提交已合并或已不需要。
- [ ] `checkout ./restore .` 会覆盖/丢弃工作区未提交改动——确认无未暂存的编辑会被丢失。
- [ ] `--force` 推送会覆盖远端历史——确认目标远端分支可由你重写，且没有他人的提交会被覆盖。
- [ ] 有没有可逆的替代方案（如用 `git reflog` 可找回的 `reset --soft`、稳妥的 `--no-force` 推送）？
- [ ] 是否已确认不会影响 `main`/`master` 等受保护分支？

### 3. 与用户确认

用 `ask_user_question` 工具一次性把"操作内容 + 潜在后果 + 是否继续"问清楚。提问应包含：

- 一个确认问题："确认执行 `<完整命令>` 吗？它将 `<具体后果>`。"
- 必要时的备选项（如"仅执行安全版本（如 `reset --soft`）"、"取消操作"）。

### 4. 执行或拒绝

- 用户明确同意 → 可执行该命令，并在执行后再快速复查一次命令参数。
- 用户不同意或无法确认 → 不执行，说明被阻止的原因及安全替代方案。

### 5. 记录护栏范围（可选）

如需给整个会话/项目建立一致的护栏，可生成一份说明文件（如 `GIT-GUARDRAILS.md`）或写入团队约定文档，列出受保护的命令清单与确认流程，供后续会话沿用。

## 危险命令清单（参考）

| 命令模式 | 危险后果 | 安全替代 |
|---|---|---|
| `git push`（含 `--force`/`--force-with-lease`） | 覆盖远端历史 | `--force-with-lease` 需小心；必要时先 `git fetch` 核对再推 |
| `git reset --hard` | 丢弃工作区/暂存区改动 | `git reset --soft`（保留改动）；或先 `git stash` |
| `git clean -f` / `git clean -fd` | 删除未跟踪文件/目录 | 先 `git clean -n`（预演列出将删项） |
| `git branch -D` | 强制删除未合并分支 | 先 `git branch -d`（要求已合并）或确认提交已备份 |
| `git checkout .` / `git restore .` | 覆盖未提交改动 | 先 `git stash` 或 `git diff` 复核 |

## 合规与注意

- 本技能是行为约束，不绕过、也不假设存在 `.claude/settings.json` 之类的 hooks 文件；DSH 环境无需也不安装此类 hooks。
- 涉及团队共享分支或他人的代码时，宁可多问一次，不轻易执行破坏性操作。

# 交接文档（Handoff）

把当前会话压缩成一份自包含的交接文档，让一个全新的代理不依赖本会话上下文也能接手继续工作。

## 触发时机

- 用户明确要求 "交接"、"handoff"、"传给下一个代理"、"让新会话接手"、"写交接摘要 / 交接文档"。
- 当前工作长或复杂，需要把进度、决策和下一步清晰记录，供稍后或由他人/另一代理继续。
- 用户在描述中声明了"下一个 session / 下一个代理要专注什么"（如传入 focus 参数）。

## 核心原则

1. **自包含**：DSH 的 `subagent` / `subagent_fork` 不会继承父会话的上下文（没有父会话对话历史），所有信息必须写进文档本身。不要写"见上面"、"见之前讨论"、"如会话前文"之类的指代。
2. **不重复已有工件**：规范/计划/ADR/issue/commit/diff 等已捕获的内容不要整段复述，用路径或 URL 引用即可。
3. **脱敏**：交接文档会作为下一个代理的上下文，必须抹掉 API key、密码、令牌（token）、凭据、个人可识别信息（PII）。
4. **只写目标**：文档聚焦"为了让新代理能立刻接手"，而非重演全部对话。

## 工作流

### 第一步：采集上下文

- 读取当前会话相关的工件：spec、plan、ADR、issue、commit、diff 等，确认哪些已在别处记录、只需引用。
- 识别尚未被记录的隐性知识：关键决策及其理由、未解决的阻塞、约定、尝过的死路。

### 第二步：撰写文档

交接文档建议包含以下小节（按需取舍，至少包含 `## 背景与目标`、`## 当前状态` 与 `## 下一步`）：

```
# <会话/任务名> 交接

## 背景与目标
为什么做这件事、要达成什么结果（自包含地描述，不假设读者见过本会话）。

## 当前状态
- 已完成：<已完成事项，引用相关工件路径/URL>
- 进行中 / 未完成：<当前卡在哪、产物在哪>

## 关键决策与理由
- <决策> —— 原因：<理由>
（记录重要的取舍，新代理不应推翻或重做决策。）

## 阻塞 / 风险 / 待确认
- <具体阻塞与建议的解决方向>

## 下一步
- [ ] <下一步动作 1>（完成标准：<怎么算做完>）
- [ ] <下一步动作 2>

## 约定与提示
- 仓库/项目约定、命令、环境注意点（按仓库现有约定；不存在则说明需先创建）。

## suggested skills
- <技能名>：<为什么建议在此处调用>
- <技能名>：<为什么>
```

## 第三步：保存或交接（按用户当前意图二选一）

**A. 保存交接文档（默认）：** 写到临时目录——优先 `$env:TEMP`（用 `pwsh` 的 `$env:TEMP`），而不是当前工作区。文件名建议 `handoff-<简短描述>.md`。之后给出路径，可说明稍后可人工发布到 issue 跟踪器等。

**B. 立即以后台代理接手：** 若用户希望"生成即交接"，用 `subagent` 工具（默认后台运行）启动一个新代理，并把交接文档内容**完整、自包含地**作为 `prompt` 传入。子代理没有本会话上下文，prompt 必须可独立执行。给 `description` 起一个描述性短名称（如 "Continue login bugfix"），便于识别。若下一步必须立即拿到结果，再设 `run_in_background: false`。

### 第四步：核对（检查清单）

- [ ] 文档自包含：不含任何"见会话前文 / 见上面"的代指？
- [ ] 只引用、不重复已捕获的工件，给出路径或 URL？
- [ ] 无 API key、密码、token、PII？
- [ ] 含 `## suggested skills` 小节并给出具体技能名？
- [ ] 若传入过 focus / 参数，已据此裁剪文档？
- [ ] 生成了清晰的 `## 下一步`（可勾选清单 + 完成标准）？
